# 백테스트 프로토콜

`/backtest` · `/backtest-refresh` 스킬과 모든 독립 백테스트 세션이 따르는 공통 규약.
이 파일을 읽지 않고 백테스트를 시작하지 않는다.

## 1. 데이터

- **로컬 캐시만 사용한다.** 재다운로드하지 않는다.
  - KR: `cache/prices_kr.parquet` · US: `cache/prices_us_test.parquet` · 지수: `cache/prices_bench.parquet`
- 결과 문서에 **데이터 기준일**(각 parquet의 마지막 봉 날짜)을 반드시 기록한다.
- 캐시 마지막 봉이 실행일보다 **6개월 이상** 오래됐으면 결과 문서와 종료 출력에
  "캐시 갱신 권고"를 명시한다 (갱신 방법: US `PYTHONPATH=. python docs/analysis/scripts/us_download.py`,
  KR은 `python -m pipeline.run --market kr`).
- **알려진 데이터 이상 — 스크립트가 직접 막아야 한다.** `btlib.loading`은 순수 parquet
  로더라 **아무것도 걸러내지 않는다.** (`btlib.engine`만 `np.all(c > 0)`으로 종가 0
  종목을 통째 제외한다. 이벤트 방식이 아니면 이 방어가 적용되지 않는다.)
  - **US**: 종가 0 구간 종목(CBIO·DEC)
  - **KR**: 거래정지 봉이 `open = high = low = 0`, `volume = 0`이고 **close만 직전가로
    이월**돼 있다(9,008봉·164종목). **`close <= 0`만 검사하면 전부 놓친다.** 체결가로
    쓰면 0으로 나누기가 발생한다 — H-010에서 실제로 equity 시리즈가 조용히 절단됐다
    (2026-08-01 §5.5 P1). OHLC를 체결에 쓰는 스크립트는 **`open <= 0`도 마스킹**하고
    체결 가능 판정에 `> 0` 조건을 넣을 것.

## 3. 사전 판정 기준 (pre-registration)

**결과를 보기 전에** 가설 문서에 통과/기각 조건을 고정한다. 최소 요건:

- **판정 지표는 그 이론이 실제로 예측하는 것이어야 한다** (아래 §3.0)
- **KR·US 양 시장에서 일관**될 것 (한 시장 통과는 "부분 지지"로만 기록)
- 비용 반영 후 기준일 것
- 한 칸만 좋은 결과는 우연으로 간주 (다중비교 경계)

### 3.0 판정 지표는 이론이 예측하는 것으로 잡는다

**기본값은 수익 지표**다 — 초과수익(벤치마크 차감)이 **평균과 중위 둘 다** 양수일 것.
대부분의 가설이 여기 해당한다.

**그러나 이론이 "수익이 는다"가 아니라 "위험이 준다"를 주장하면, 수익 지표로
검정해서는 안 된다.** 그러면 **이론이 말하지도 않은 것을 시험**하게 되고, 기각이
나와도 그 기각은 이론에 대해 아무것도 말해주지 않는다.

| 이론이 주장하는 것 | 주 판정 지표 | 예 |
|---|---|---|
| 수익이 는다 | 초과수익 평균·중위 | 모멘텀 프리미엄, 선정 규칙 개선 |
| **변동성·낙폭이 준다** | **분산비 `log(σ²_A/σ²_E)` · MDD** | 분산투자 제약, 상관 상한 |
| **결과의 편차가 준다** | **리밸일 변형 간 산포** | 리밸런싱 시점 분산(timing luck) |
| 위험조정 수익이 는다 | ΔSharpe (Memmel 보정) | 변동성 타깃 |

**수익 지표를 버리려면 아래를 모두 충족해야 한다.** 하나라도 못 지키면 수익 지표를 쓴다.

1. **출처 원문을 직접 확인하고 그 논문의 헤드라인 결과 표를 인용한다.**
   "위험 감소 논문일 것 같다"는 인상으로 판단하지 않는다.
2. **그 지표에도 §3.1-3의 척도 불변 비교를 적용한다** — 필요치뿐 아니라
   **달성 가능치도 사전에 계산**해 나란히 적는다. 한쪽만 계산하면 비교가 아니다.
3. **분산비 검정의 SE는 등분산 가정에 의존한다.** 월별 시장 변동성이 크게
   변하면 `4(1−ρ²)/(n−1)` 근사는 SE를 과소평가한다. 이 데이터에서 실측 보정계수는
   **KR 1.24~2.21배 · US 1.09~1.34배**이고, 보정 전 95% CI의 실제 커버리지는
   **KR 62%**까지 떨어진다. 따라서 **월 블록 부트스트랩이나 부호 뒤집기
   순열검정**으로 CI를 내거나, 보정계수를 문서에 명시하고 MDE에 곱해야 한다.
4. 지표를 **결과를 본 뒤에 바꾸면 사전등록이 무효**다.

> **실패 사례 — H-017** ([2026-08-06](backtests/2026-08-06-correlation-cap.md)).
> 상관 상한 가설을 "이 문헌들은 위험 감소를 주장한다"며 분산 지표로 바꿨는데,
> 게이트가 원문을 확인하니 **셋 중 둘이 명시적으로 수익 개선을 주장**했다
> (Choueifaty & Coignard 2008 Exhibit 2: 연 수익 12.7% vs 벤치 9.6% · Sharpe
> 0.66 vs 0.39, 그리고 **MDP의 변동성은 최소분산 포트폴리오보다 높다**;
> López de Prado 2016은 제목이 "…that **Outperform** Out of Sample").
> **유리한 지표를 찾아 옮겨간 것**이 됐고 게이트에서 종료됐다.
> 위 1~3은 그 재발을 막기 위한 조항이다.

### 3.1 이 시스템의 검출 한계 — 설계 전에 반드시 확인

> 출처: **H-014 메타 분석** ([2026-08-02](backtests/2026-08-02-mde-power-analysis.md)).
> H-010·H-012·H-013의 신뢰구간 20칸에서 **MDE**(최소검출가능효과 = 2.8016 × 표준오차,
> α=5%·검정력 80%)를 산출한 결과다.

**결론: 실제로 테스트한 20칸 중 18칸(90%)은 문헌 수준의 효과(연 4%p)가 실제로
있었더라도 검출하지 못했을 설계였다.** 즉 지금까지의 기각 상당수는 "효과 없음"이
아니라 **"애초에 답할 수 없는 형태의 질문"**이었다.

**차이를 만드는 것은 표본 수가 아니라 대조군의 겹침이다.** H-010 ④와 H-012 ④는
둘 다 `A−E` 월별 차분이고 표본수도 같은데(KR 134 · US 168개월), 대조군 구조만
달라 **필요 표본이 52~292배** 차이났다.

| 대조군 유형 | 검출 가능한 최소 효과 | 연 4%p에 필요한 표본 | 판정 |
|---|---|---|---|
| **겹치는 대조군** — 부품 하나만 제거해 `A ⊂ E` | 월 0.12~0.21%p (연 1.4~2.5%p) | **21~52개월** | **권장** |
| 무작위 대조군 (`A−D`) | 월 0.73~0.90%p (연 8.7~10.8%p) | 810~987개월 | 경계 |
| **정렬 기준 교체·반전** | 월 1.18~1.99%p (연 14~24%p) | 1,724~6,134개월 | **비권장** |
| **종목 수준 이벤트 스터디** (짝 70~133일) | 월 1.0~5.1%p (연 12~61%p) | 측정 불가 | **비권장** |

**가설 설계 시 지켜야 할 것**

1. **대조군은 결과 포트폴리오가 최대한 겹치도록 짠다.** "규칙 문장 하나만 바꿨다"로는
   부족하다 — 정렬 기준을 바꾸면 문장은 하나여도 담는 종목이 통째로 달라져 검출력을 잃는다.
2. **사전 등록 시 그 조건의 MDE를 실제로 측정해 문서에 숫자로 적는다.**
   기존 테스트의 SE를 참고하거나, 차분 시계열의 SE를 직접 재서
   `2.8016 × SE`를 산출한다. **결과를 보기 전에 한다.**
   - 측정 코드는 **SE만 산출하고 평균·t값은 계산 경로를 두지 않는다.**
     점추정치를 보면 사전등록이 무효가 된다 (H-015 §5.1의 방식).
   - **검정력은 "판정 규칙의 실효 검정력"으로 계산한다.** 시장별 검정력이 아니다.
     PROTOCOL §3은 **양 시장 모두** 충족을 요구하므로 판정 규칙은 **교집합**이고,
     실효 검정력은 **곱**이다.

     > H-020 실측: 시장별 54.3% · 27.8% → **실효 15.1%**. 저자는 시장별 값으로
     > "종료 사례(5~10%)와 질적으로 다르다"고 주장했으나, 판정 대상이 아닌 양이었다.
     > 곱으로 내면 같은 구간이다. 이 착각은 **검정력을 3~4배 과대평가**시킨다.

   - **검정력은 비용 반영 후 효과로 계산한다.** 처치가 회전율을 올리면 효과가
     잠식된다. 판정 기준이 "비용 후"인데 검정력이 gross면 **서로 다른 양**이다.

     > H-020 실측: 처치군 회전율 +7.50%p/월(KR) → 기대효과의 **27.8% 잠식**,
     > 실효 검정력 15.1% → **7.8%**.
3. **MDE는 반드시 처치 강도로 정규화해 비교한다** — `MDE < e*` 만으로는 부족하다.

   > **왜**: 처치 강도를 줄이면 MDE는 얼마든지 작아지지만 **검출력은 하나도 늘지
   > 않는다.** H-015 §5.3이 이를 수학적으로 보였다 — 비중 틸트 설계에서
   > 차분이 `d_λ = λ · d_1` 로 정확히 비례하므로 **평균도 SE도 λ배가 되어
   > t는 λ에 완전히 불변**이다(실측으로 소수 셋째 자리까지 확인). 고정 문턱만
   > 보면 **처치를 줄여 문턱을 넘긴 무의미한 설계가 통과한다.**

   올바른 기준은 척도 불변이어야 한다.
   ```
   필요 효과 = MDE / 처치 비중
   ```
   이 값이 **해당 문헌이 보고하는 효과 크기보다 크면 측정 불가**다.
   (예: 20종목 중 5종목 교체 = 처치 비중 25%. MDE 1.22%p면 교체된 다섯 쌍이
   월 4.9%p = 연 59%p 벌어져야 한다 → 문헌 값 연 10~15%p의 4배 → **측정 불가**.)
4. **종목 수준 이벤트 스터디는 이 데이터로 결론을 못 낸다.** 진단 목적으로만 쓰고
   판정 근거로 쓰지 않는다.
5. **"N종목 중 k개 교체" 설계는 사전에 `σ_δ` 를 직접 재라.**

   > 게이트 미통과 4건(H-011·H-015·H-017·H-018)이 전부 이 형태였다. 원인은
   > 신호가 아니라 **형태**다 — 같은 데이터에서 신호를 5종으로 바꿔도 `σ_δ` 는
   > **US 23.5~27.3(1.16배)** 에 머문다. 개별 종목 월수익의 산포가 지배하기 때문이다.

   ```
   필요 짝-월 = (2.8016 × σ_δ / e_pair)²      ·      가용 ≤ k × 강세 달
   ```
   `σ_δ` = 교체된 짝의 월수익 차의 표준편차. **`가용 ≤ k·n` 은 부등식이므로,
   가장 유리한 경우로 계산해 미달이면 어떤 가정에서도 미달**이다.
   실측 결과 이 데이터에서는 **6~30배 미달**이었다.
   측정: `backtests/scripts/swap_design_bound.py --sigma --bound`
   ([H-019](backtests/2026-08-11-swap-design-power-law.md) — 문서는 게이트 미통과이나
   유도·구현은 독립 검토를 통과했다).

   **수치를 다른 신호에 이식하지 말고 각 가설이 자기 `σ_δ` 를 재라.**

6. **절대 성과(CAGR·MDD)를 보고할 때는 리밸일 변형의 산포를 함께 보고한다.**

   > **리밸런싱 날짜만 바꿔도 KR CAGR이 3.67% ~ 13.08% 로 갈린다**(9.41%p, 표준편차
   > 4.02%p). US는 1.43%p. 규칙은 글자 하나 다르지 않다
   > ([H-016](backtests/2026-08-11-rebalance-timing-luck.md)).
   >
   > **찾으려던 신호(연 4%p)보다 이 잡음이 크다.** 단일 리밸일 결과를 단독으로
   > 제시하면 안 된다. **4.02%p(KR) 미만의 CAGR 차이는 우위의 근거로 쓰지 않는다.**
   >
   > 차분(A−E)은 양쪽 팔이 같은 리밸일을 쓰면 대부분 상쇄되므로 안전하다 —
   > 지금까지의 ablation 설계는 이 점에서 문제가 없었다.
   > 측정: `backtests/scripts/timing_luck.py --measure`

7. **검출 한계에 걸리면 테스트를 실행하지 않고 게이트에서 종료한다.** registry에
   `게이트 미통과`로 기록하고 사유를 남긴다. **"기각"이라고 쓰지 않는다** —
   돌리지 않았으므로 효과의 유무에 대해 아무것도 주장하지 않는다.

> **주의 — 위 표의 근거 칸 수는 행마다 2~12칸으로 다르다.** "권장" 행은 단일
> 테스트의 2칸에서만 나왔고, 유형 분류 자체가 H-014의 **사후 탐색**이다(H-014 §7-4).
> 수치를 기계적으로 적용하지 말고 **"겹치는 대조군을 설계하라"는 방향**으로 쓴다.

      문서가 자각하고 있는가. 근거 없이 "정렬 기준 교체"·"이벤트 스터디" 유형을
      판정 근거로 삼으면 **미통과**)
- [ ] 5. 매수·매도 규칙이 일봉 종가 기준으로 모호함 없이 기술됨
- [ ] 6. **문서에 적은 수식·산식이 검증됐음** (아래 참조)

#### 게이트 횟수 — 기본 3회, 조건부 5회

**1·2·3이 걸리면 그 가설은 가망이 없다. 4·5·6은 명세를 다듬으면 수렴한다.**
둘을 같은 횟수로 묶으면 멀쩡한 가설이 서술 정밀도 때문에 버려진다(H-012 실패).

- 기본 **3회**. 3회 안에 통과하지 못하면 기각.
- **예외**: 매 회차 **1·2·3을 전부 통과**했고 4·5·6에서만 걸렸다면 **최대 5회까지 연장**.
- 연장 중이라도 아래 하나라도 해당하면 **즉시 종료(기각)**:
  - 새 회차에서 1·2·3 중 하나가 걸림 → 가설 자체의 문제
  - **같은 지적이 2회 연속 반복** → 수렴하지 않는다는 신호
  - 수정이 **새 결함을 만드는 일이 2회 연속** 발생 → 설계자가 명세를 통제하지 못하는 상태
- 기각 시 registry 결과 요약에 **"게이트 미통과(테스트 미실행)"**과 최종 사유를 남기고,
  설계 문서는 지우지 않는다(재시도 시 출발점).

#### 항목 6 — 수식·산식 검증

게이트 단계에는 코드가 없어 수식 오류가 그대로 통과한다. H-012 3차에서 실제로
**Memmel 신뢰구간의 SE 스케일 누락**(CI 폭이 1/400)과 **재배분 예산 산식이 의도와 반대**
두 건이 이 공백으로 들어왔다. 따라서 **문서에 수식·산식을 적었다면 다음 중 하나를
문서에 함께 남긴다**:

- **극단값 확인**: 알려진 경계에서 값이 맞는가 (예: 두 계열이 동일하면 ΔSharpe의 SE는
  0, 독립이면 √(2/T)에 수렴)
- **차원 확인**: 좌변과 우변의 단위가 같은가 (Sharpe는 무차원인데 우변이 수익률² 차원이면 오류)
- **소형 수치 예제**: 손으로 계산 가능한 입력에서 기대값과 일치하는가

검토자는 이 검증이 **없거나 틀렸으면 항목 6을 미통과**로 판정한다.

### (b) 코드 + 결과 검토 — 테스트 후, 독립 sub-agent(Opus), 1회

- [ ] look-ahead 없음 (미래 봉·최종일 기준 필터·`tail()` 사용 여부 grep)
- [ ] 유동성 필터가 진입 시점 기준(PIT)인가 (US)
- [ ] 벡터화 로직은 소표본 루프 구현과 대조했는가 (2026-07-29 §5-① 재발 방지)
- [ ] 비용 반영, 겹치는 창이면 독립 표본수 명시, 생존편향 한계 명시
- [ ] `btlib` 공용 모듈을 사용했는가 (새로 짠 부분은 왜 필요했는지 설명)
- [ ] 결과 판정이 사전 기준·실제 숫자와 일치하는가

### (c) 문서 검토 — 아카이브 작성 후, 독립 sub-agent(Opus), 1회

- [ ] 가설·설계·사전 기준·데이터 기준일·시드·결과·판정·한계가 모두 있는가
- [ ] 숫자가 스크립트 출력과 일치하는가
- [ ] 재현 방법(실행 명령)이 있는가

## 5. 아카이브 규칙

- 결과 문서: `docs/analysis/backtests/YYYY-MM-DD-<slug>.md`
  (필수 섹션: 가설 / 사전 판정 기준 / 설계 / 데이터 / 결과 / 판정 / 한계 / 재현 방법)
- 테스트 스크립트: `docs/analysis/backtests/scripts/<slug>.py` (btlib 사용)
- registry 상태 갱신(`채택`/`기각`) + `SUMMARY.md` 맨 위에 초보자 요약 추가
- **테스트당 git 커밋 1개. push는 하지 않는다** (사용자 판단)

## 6. 운영 규칙

- **수정 허용 경로**: `docs/analysis/**` 만. `pipeline/` `site/` `tests/` `scripts/`
  `.github/`는 읽기 전용 (import는 허용, 수정 금지)
- **동시 실행 금지**: registry·SUMMARY는 공유 파일이므로 백테스트는 한 번에 한 세션만
- **모델 배분**: 본 분석·문서 작성은 Opus 세션 권장. **§4의 검토 3종((a)(b)(c))은
  모두 독립 sub-agent + Opus 고정.**
  - **독립성이 필수 조건이고, 모델 등급은 그 위에서 검출력을 정한다.** 코드를 작성한
    세션이 자기 코드를 직접 검토하면 같은 가정을 그대로 들고 보게 되므로, Opus로 해도
    게이트가 무력해진다. 그래서 반드시 sub-agent로 띄우고, 그 위에 등급을 올린다.
    (이 제약은 §4의 검토 3종에 적용된다. `/backtest-refresh`의 수혈 판정은 본 세션이
    직접 수행하며 여기에 해당하지 않는다.)
  - 등급을 올리는 이유는 **위험의 비대칭**이다. 작성 실패는 재실행으로 되돌릴 수 있지만,
    검토 실패는 조용히 통과해 **틀린 결론이 아카이브에 영구 기록**되고 registry가 그것을
    근거로 이후 가설의 중복을 판정하므로 오류가 뒤 테스트로 전파된다.
  - 특히 (b)는 신규 계산 로직의 버그를 찾는 판단 작업이다. 이 프로젝트에서 확인된 버그는
    전부 신규 구현 코드에서 나왔다(2026-07-29 §5의 벡터화 연속 카운트 오류·거래대금
    필터 look-ahead).
- 테스트 종료 시 SUMMARY.md의 해당 항목을 **화면에 그대로 출력**한다
