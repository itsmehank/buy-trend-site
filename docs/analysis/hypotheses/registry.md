# 가설 대장 (registry)

백테스트한 가설과 대기 중인 가설을 모두 기록하는 단일 장부. **모든 백테스트는
시작 전에 이 파일과 `jail.md`를 읽고 중복을 대조해야 한다.** (`/backtest`,
`/backtest-refresh` 스킬이 사용)

## 상태 정의

| 상태 | 의미 |
|---|---|
| `후보` | 수혈(`/backtest-refresh`)로 들어와 판정 대기 중. `시도 n/3` 카운트를 함께 기록 |
| `대기` | 판정 통과, 테스트 대기 중인 풀 |
| `채택` | 테스트 완료 — 사전 판정 기준 통과 |
| `기각` | 테스트 완료 — 사전 판정 기준 미달 |
| `완료(메타)` | 전략 가설이 아니라 **시스템 자체를 측정**한 분석. 채택/기각 대상이 아니다 |
| `게이트 미통과` | 가설 게이트에서 종료 — **테스트 미실행**. 효과의 유무를 주장하지 않는다 |
| `감옥` | 이 시스템에서 테스트 불가 → `jail.md`로 이동, 재유입 금지 |

## 가설 키 형식 (중복 판정 기준)

`진입: … | 매도: … | 레짐: … | 시장: …` — 네 요소가 모두 같으면 중복이다.
파라미터 숫자만 다른 변형(예: SMA120 vs SMA200 돌파)은 **구조가 같으면 중복으로
간주**한다. 단, 기존 테스트가 명시적으로 남긴 미검증 영역(레짐 분리, 재진입·
리밸런싱, 포트폴리오 단위)은 새 구조로 인정한다.

> 매월 마지막 거래일 종가 판단 → **익일 종가 체결** / 레짐 = 지수 > SMA200일 때만
> 정상 운용 / 매도 = 랭킹 40위 밖 이탈 시 교체(40위 버퍼는 회전율 억제).
>
> **테스트 순서와 다중비교** — 부품 3개를 한 베이스라인에 붙이므로, 효과가 전혀
> 없어도 셋 중 하나가 p<0.05로 나올 확률이 약 14%다. 수혈 답변의 권고대로
> **1순위 H-016**을 먼저 돌리고, 판정 임계는 `/backtest` 2단계에서 다중비교를
> 반영해 고정한다.
>
> **등재 시 확인된 우려 (각 가설의 `/backtest` 2단계에서 반드시 해소할 것)**
>
> - **H-016은 부품이 하나가 아니다.** 트랜치 분할이 (a) 리밸런싱 시점과
>   (b) **레짐 이탈 시점**을 동시에 바꾼다("지수 < SMA200이면 해당 트랜치만 현금화").
>   깨끗한 ablation이 되려면 **레짐 이탈은 양쪽 팔에서 동일하게(전체 동시 청산)**
>   두고 랭킹 기반 회전만 분산해야 한다.
> - **H-016의 판정 지표가 평균이 아니다.** 원 논문의 주장은 "수익률을 높인다"가
>   아니라 **"결과의 분산을 줄인다"** 이므로 `E[A−E] ≈ 0` 이 이론의 예측이다.
>   PROTOCOL §3의 최소 요건(초과수익 평균·중위 양수)을 그대로 적용하면 **이론이
>   예측하지 않는 것을 검정**하게 된다. 사전 등록에서 **산포 기준 지표**로 바꾸고,
>   §3.1 검출 한계도 그 지표에 맞춰 사전 측정해야 한다.
> - **H-017·H-018의 임계값은 P&L을 보기 전에 고정한다.** 수혈 답변이 권한
>   "발동 개수 사전 스캔"은 **PROTOCOL §3.1-2가 요구하는 처치 강도 측정과 같은
>   작업**이므로 정당하다. 단 **랭킹·상관행렬·거래량만 보고 조정**해야 하며,
>   수익률을 본 뒤 임계를 고르면 사전등록이 무효가 된다.
> - **H-018은 원 논문의 지표를 대체했다.** 회전율 → 자기 이력 대비 상대거래량.
>   원 결과의 재현을 주장할 수 없고, 결과 해석에 이 사실을 명기해야 한다.
